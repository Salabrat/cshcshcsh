# ✏️ Фикс: не сохранялись названия, описания, названия кнопок и реквизиты

## Симптомы (как это выглядело для владельца)

| Что делали | Что происходило |
|---|---|
| Изменить категорию/тему → **Название** | Ввёл текст → бот показал меню (Каталог/Профиль…), имя **не сохранилось** |
| Изменить категорию/тему → **Описание** | То же самое — ввод «проглатывался» |
| Изменить категорию/тему → **Фото** | ✅ Работало |
| `/editbutton` → переименовать кнопку меню | Ввёл название → ничего не сохранилось |
| `/edit` → **Изменить текст** (приветствие) | Вообще никакой реакции |
| `/cards` → изменить реквизиты (карта/СБП/крипта) | Ввёл реквизиты → не сохранилось |

Почему фото работало, а текст — нет: фото приходит как `content_type=photo` и попадает в
отдельный обработчик, а **текст перехватывался раньше**, чем доходил до формы.

---

## Корневая причина

В `streetshop.py` есть глобальный обработчик текста кнопок меню:

```python
@dp.message_handler(lambda message: message.text and not message.text.startswith('/'), state='*')
async def handle_menu_buttons(message: types.Message): ...
```

Он стоит **строкой 3053**, а формы редактирования объявлены **позже**
(`admin_edit_catalog_name_save` — строка 6029, реквизиты — 9592, кнопки — 14423 и т.д.).

aiogram 2.x запускает **первый подходящий** обработчик и на нём останавливается —
в `aiogram/dispatcher/handler.py`:

```python
response = await handler_obj.handler(*args, **partial_data)
if self.once:              # once=True по умолчанию
    break                  # остальные подходящие хендлеры уже не вызовутся
```

Фильтр `state='*'` подходит **в любом** состоянии, поэтому текст, введённый в форме,
перехватывался меню: не совпадал ни с одной кнопкой → уходил админам в поддержку
(`forward_user_message_to_admins`) → а до `waiting_for_name` / `waiting_for_card` не доходил.

Фото спасало то, что у него другой `content_type`, а фильтр меню пропускает только текст.

Дополнительно: состояния `WelcomeEditStates.waiting_for_text` (текст приветствия)
**вообще не имело обработчика** — поэтому `/edit` → «Изменить текст» молчал.

---

## Что исправлено

### 1. `handle_menu_buttons` пропускает ввод, относящийся к активной форме

Добавлен импорт и реестр состояний:

```python
from aiogram.dispatcher.handler import SkipHandler
```

Реестр заполняется один раз при загрузке модуля (`collect_fsm_message_states(dp)` —
в самом конце файла, когда объявлены все хендлеры) и содержит **70** состояний, у которых
есть собственный `message`-обработчик.

Если текст не совпал ни с одной кнопкой меню и у пользователя активно такое состояние —
обработчик делает `raise SkipHandler()`, и апдейт уходит **следующему** подходящему
хендлеру, то есть форме:

```python
if current_state and current_state in FSM_STATES_WITH_MESSAGE_HANDLERS:
    print(f"Активна форма '{current_state}' — передаём ввод её обработчику")
    raise SkipHandler()
```

Такой подход автоматический: любое **будущее** состояние с обработчиком защищено от перехвата,
список вести руками не нужно.

### 2. Добавлен отсутствовавший обработчик текста приветствия

```python
@dp.message_handler(state=WelcomeEditStates.waiting_for_text)
async def process_welcome_text(message: types.Message, state: FSMContext):
    ...  # сохраняет welcome_text с HTML-форматированием
```

## Важно знать

- Фикс универсальный: он лечит **все** формы редактирования (каталог, товары, файлы,
  бонусы, поддержка, рассылки, админы), а не только перечисленные в жалобе.
- После правок **перезапустите бота** — реестр строится при старте, в логе появится строка:
  `✅ Состояний FSM с собственными message-хендлерами: 70`.
- Нормальное поведение сохраняется: текст, не относящийся к форме, по-прежнему уходит админам
  как обращение в поддержку.
